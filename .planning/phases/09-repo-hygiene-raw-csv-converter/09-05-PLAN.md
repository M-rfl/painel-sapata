Decisions:
- Report: console summary + markdown file next to the output, NOT in `site/`. Default report path: `<run_dir parent>/validation-<run_id>.md` (for `Results_1st.Run/raw` -> `Results_1st.Run/validation-<id>.md`, inside the ignored folder).
- Golden constants come from `--golden` (committed `tests/fixtures/golden_run1.json`); "exact" block is hard-checked, "reference" block is side by side only. Pontos (101) is NEVER a hard assertion.
- Workbook reading is optional (`--workbook`), slow (minutes): openpyxl `load_workbook(path, read_only=True, data_only=True)`, sheet found by name prefix '02', columns found by header text. openpyxl is imported lazily inside `read_workbook` so the converter runs without it.
- Fail the run only on structural problems or when the recovered row count != golden rows (StructuralError, exit 1). Exact-match KPI mismatch -> report FALHA + exit 2 (JSON is still written so it can be inspected).
- Report language: Portuguese, pt-BR number formatting (21.031), file written with encoding='utf-8'. Console: call `sys.stdout.reconfigure(encoding="utf-8")` (cp1252 crashes on '—'/'Ç' otherwise).
- Explain, don't hide: per-trecho differences are expected (folded tunnel trecho; geofence vs manual boundaries; sub-second vs 1 s resolution; 2.020 sem GPS rows vs the workbook's 882-row 'Dentro do Túnel' label of which only 108 lack coordinates).
</context>
