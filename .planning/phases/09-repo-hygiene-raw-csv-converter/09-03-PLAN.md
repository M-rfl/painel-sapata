Implement in `geofence.py` (stdlib + geo.haversine_m only):

`score_lines(lat, lon, lines, radius_m=100.0, terminal_radius_m=200.0) -> list[LineScore]` (sorted best first):
- lat/lon are per-sample `float | None` lists (convert Decimal upstream).
- observed = set of codes of ANY station of ANY line within radius_m of any coordinate sample (nearest station per sample).
- For line L: hits_L = codes of L's stations hit (terminals of L use terminal_radius_m, others radius_m). in_line = |hits_L|; terminals = |terminals(L) ∩ hits_L|; off_line = |observed − codes(L)|. score = in_line + 3*terminals − 2*off_line.
- Performance: precompute per sample only for coordinate changes (consecutive identical coordinates share the result) — 23k samples x ~40 stations is fine but cache by coordinate.

`assign(lat, lon, lines, *, radius_m=100.0, terminal_radius_m=200.0, line_override=None, timestamps=None) -> Assignment` — this task implements the segmentation core (private helpers) and returns segments + passages + turnarounds; Task 3 completes trecho runs/flags and the Assignment assembly. Algorithm:
1. Line choice: override if given (note 'line override: N'); else best score; `ambiguous = len(scores) > 1 and scores[0].score - scores[1].score < 1`; notes include best and runner-up scores.
2. `r(station, seq)` = terminal_radius_m if station is seq[0] or seq[-1] else radius_m.
3. Initial direction: collect the first 3 distinct restricted hits (stations of the chosen line, nearest within r). Choose the direction in which their indices increase most (count increasing consecutive pairs); tie -> the direction whose first station equals the first hit; still tied -> direction 0 (note it). No hits at all -> direction 0, whole run flagged edge (note).
4. Forward-only state machine over coordinate samples (None samples skipped by the machine; they inherit by index later). State: seq S, j (index of last entered station, -1 = none), dwelling (bool), enter_idx/leave_idx per station.
   - While dwelling at S[j]: if sample inside r(S[j]) -> continue; else record boundary_idx(j) = this sample index; dwelling = False.
   - Candidates S[j+1 .. min(j+3, last)]: first k inside r -> entered k at sample i; stations j+1..k-1 become 'inferred' (boundaries resolved in Task 3); j = k; dwelling = True.
   - Terminal arrival: when j == last and the train leaves r(S[last]) -> Turnaround(method='terminal') at that sample; start new segment with the opposite direction, j = 0 (its first station = this terminal, status 'hit', boundary_idx = turnaround index), dwelling False.
   - Reversal fallback: when not dwelling and j >= 1, a sample inside r(S[q]) with q <= j (a station already passed) is a candidate backward hit q1 (remember its index); confirmed when a later sample is inside S[q2] with q2 < q1. A forward hit before confirmation clears the candidate. On confirmation: inferred terminal T = S[last]; stations S[j+1..last] are 'inferred' for this segment; turnaround index t* = the coordinate sample with minimum haversine to T among samples in (leave index of S[j], first sample of q1]; close the segment at t* (Turnaround(method='reversal')) and RE-RUN the machine from t* with the opposite direction, j = 0 (terminal status 'inferred').
   - Every passage records min_dist_m = min distance from any coordinate sample in its segment window.
5. gap_s: if timestamps given, the max consecutive-sample gap inside [arrival/leave window of the turnaround]; report only.
Keep segmentation in a private `_segment(...)` returning a list of segment records (direction index, start index, per-station enter/leave/status/min_dist) so Task 3 can build trechos. Document the algorithm in the module docstring (why forward-only: Wi-Fi fixes are noisy, per-station 'last fix inside' produced non-monotone boundaries in research).
