Design decisions (made here, no CONTEXT.md):
- Panel contract: each panel module exports `render(el, ctx)` where `ctx = { run, analysis, view, state, stats: {mm, table}, quality }`. Panels rewrite `el` (via `dom.js` helpers) on every call; no framework.
- `dom.js`: `h(tag, attrs, ...children)` creating elements with `textContent` for strings (never innerHTML with data → no injection), `clear(el)`. This is the only DOM helper module.
- Layout: CSS grid — header (title, run date via fmtDateTime(meta.t0), badge), left column reserved for controls (`<aside id="controls">`, filled by Plan 06; render a placeholder text now), main column with sections `#overview`, `#classes`, `#stats`, `#quality`. Collapse to one column under 900 px (cheap protection for the public link; full mobile is deferred MOB-01).
- Severity farol colours as CSS variables: Normal #2e7d32 (verde), Leve #f9a825 (amarelo), Moderado #ef6c00 (laranja), Severo #c62828 (vermelho), Crítico #6a1b9a (roxo). Class bars are plain `<div>` with `width: %` — no chart library (Phase 12 owns charts).
- Badge: `analysis.conforme.available === false` → no badge; `ok` → green 'Conforme planilha' with `title` = T badge explanation; not ok → amber 'Divergente da planilha' with `title` = reasons joined by '; '. Never claim pontos equal the workbook; show the neutral pontos note under the pontos card when `run.reference?.pontos` exists.
- Recompute split: `analyze` only when `paramsKey(state.params)` changes (memo); `buildView`, stats and table on every state change; `qualitySummary` once at load (full-run).
