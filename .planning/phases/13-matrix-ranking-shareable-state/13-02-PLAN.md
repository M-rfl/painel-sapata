```js
export function haversineM(lat1, lon1, lat2, lon2)  // mirror geo.py exactly, R = 6371000
export function gpsKey(gps)                          // `${gps.maxSpeedKmh}|${gps.maxFixGapS}`
export function rejectedFixes(run, gps)              // number[] ascending
export function applyGpsFilter(run, gps)             // {...run, fix, locId, priorFix, gpsRejected}
```
Algorithm (RESEARCH Pattern 1): walk fixes f = 0..nFix-1 in index order; skip if fixLat[f] or fixLon[f] is NaN or fixRow[f] < 0; with prev = last accepted fix, `dt = (tMs[fixRow[f]] - tMs[fixRow[prev]]) / 1000`; if `dt > 0 && dt <= maxFixGapS` and `haversineM(...) / dt * 3.6 > maxSpeedKmh` -> reject (continue without updating prev); otherwise accept (prev = f). Fixes separated by more than maxFixGapS are accepted unchecked (a turnaround/tunnel gap is not a jump).

applyGpsFilter: when nothing is rejected return `{ ...run, gpsRejected: [] }` (no array copies). Otherwise copy `fix`, `locId` (Int32Array.from), set rows whose fix is rejected to -1 in both, and recompute `priorFix` with the decodeRun loop using the filtered fix array. `fixRow`, `fixLat`, `fixLon`, `flags` stay shared (heatPoints skips rows with fix -1). No string re-keying is needed: `locId -1` is exactly the "SEM GPS | trecho" branch of pointsByLocation.

Tests in `tests/js/gpsfilter.test.js` per <behavior>; import analyze from `../../site/js/core/index.js`.
