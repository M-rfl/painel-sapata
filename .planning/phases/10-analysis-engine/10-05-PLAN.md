## Fixture design (decided)
```json
{ "generator": "python -m tools.dashboard_converter.gen_parity", "seed": 20261002, "oracle": "analysis_ref",
  "inputs_sha256": { "site/data/run-2026-10-02-l4-t102.json": "<sha256 of analysis inputs>" },
  "cases": [
    { "name": "synthetic-01-...", "source": "synthetic",
      "input": { "ax": [...], "ay": [...], "az": [...], "t_ms": [...], "loc": [...], "trecho": [...], "trechos": [...], "source": [...] },
      "params": { "thresholds_g": [...], "offset": {...}, "gap": 1, "maxJumpMs": 2000 },
      "expected": { ... } },
    { "name": "run1-07-...", "source": "site/data/run-2026-10-02-l4-t102.json", "params": {...}, "expected": {...} } ] }
```
- `expected` keys (snake_case, from the oracle): medians_lsb, offsets2, class_counts, eventos, impactos, impact_starts, impact_peaks, impacts_by_class, pontos, point_rows, points_by_class, unclassified, class_digest, per_trecho (list in trecho order of `[records, eventos, impactos, pontos]`), priority (list of `[trecho_name, level, top_count, peak_dom2]` in sorted order), region_records, region_eventos.
- `inputs_sha256` hashes ONLY the analysis inputs (sha256 of `json.dumps([t.dt_ms, accel.ax, accel.ay, accel.az, fix_runs, trecho_runs, source_runs, gps.lat, gps.lon, [t.name for t in trechos]], separators=(",",":"))`), so regenerating the JSON with a new `generated_at` does not mark the fixture stale. Changed data does.
- Output is deterministic: no timestamps; `json.dumps(obj, ensure_ascii=False, indent=None, separators=(",", ":"))`, with one case per line allowed for readable diffs (write `[` + ",\n".join(case dumps) + `]` inside the object, or plain compact; either way the generator and the guard use the same function).
- Synthetic trecho names must be unique per index (the JS no-GPS key `-1 - trecho` is equivalent to Python `"SEM GPS | " + name` only then).
- Thresholds: always strictly increasing and rounded to 2 decimals. Include non-dyadic values (e.g. 0.7, 1.1) and the defaults.
- Manual offsets in g: rounded to 6 decimals, plus at least one exact half-step (k/4096 with k odd) and one negative half-step (e.g. -0.0003662109375 = -1.5/4096) to exercise half_up.
- maxJumpMs pool: {2000, 1000, 500, 150} (150 < the ~180 ms sample period, so most events split: a stress case).
- gap pool: {0, 1, 2, 3, 5}.
