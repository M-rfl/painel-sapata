## Parity Contract (single definition; 14-RESEARCH and 14-05 state the same)

Defined once in `tests/js/convert_meta.js` and used by both parity tests:

| Comparison | Reference | Meta keys ignored (both sides) | Everything else |
|------------|-----------|--------------------------------|-----------------|
| SC2c fixture parity (CI) | Python `build_site_json` output generated by `gen_upload_parity.py` with DEFAULT CLI args (`run_id = <date>-l<line>`, `title = Linha N · dd/mm/aaaa`, no golden) | `UPLOAD_ONLY_META` = `generated_at, converter_version, title, uploaded` (run_id IS compared) | deep-equal |
| SC2d run-1 parity (local only) | committed `site/data/run-2026-10-02-l4-t102.json` (built with `--run-id`, `--title`, `--golden`, which change only these meta keys) | `RUN1_IGNORED_META` = `run_id, title, workbook_reference, uploaded, generated_at, converter_version` | deep-equal (whole object incl. sensor_id, source.files names + sha256, t0, tz, n, t_quality, axes, workbook_defaults, line, geofence, gps_decimals, all arrays, quality) |

Float tolerance is allowed ONLY on geofence `min_dist_m` / unrounded turnaround `gap_s` in the geofence fixture test (1e-9 relative; libm ulp). Everything else is exact.
