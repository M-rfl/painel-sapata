## Phase Details

### Phase 9: Repo Hygiene & Raw CSV Converter
**Goal**: The run data is safely excluded from git and one command turns the raw logger CSVs into trustworthy site JSON that matches the treated workbook
**Depends on**: Nothing (first phase of v1.3; the `.gitignore` commit comes before anything else)
**Requirements**: REPO-01, CONV-01, CONV-02, CONV-03, CONV-04, CONV-05, CONV-06, CONV-07
**Success Criteria** (what must be TRUE):
  1. `git status` shows run data, workbook, logs, docs and caches as ignored, and `.gitignore` is the first commit of the milestone
  2. Engineer runs one command on `Results_1st.Run/raw/` and gets schema-versioned compact JSON from both the clean comma CSV and the pt-BR `;` CSV, with any unrecoverable mangled value reported rather than guessed
  3. Every sample carries a trecho from the station geofences (Line 4 and Line 1, both directions), sentido is detected from the station sequence, and tunnel samples without GPS inherit trecho from neighbours and are flagged "sem GPS"
  4. The converter's validation report shows class counts 21.031/1.611/512/173/56, eventos 2.352 and impactos 1.749 equal to the workbook, with pontos and per-trecho differences listed side by side with explanations
**Plans**: 6 plans

Plans:
- [x] 09-01-PLAN.md — `.gitignore` as first v1.3 commit, repo-hygiene test, track Stations_GEO + doc generators (W1)
- [x] 09-02-PLAN.md — Converter package + shared contracts, mangled-value recovery, raw CSV reader, golden fixture (W2)
- [x] 09-03-PLAN.md — Station-file parser + geofence trecho/sentido state machine, sem GPS/edge flags (W3)
- [x] 09-04-PLAN.md — GPS fixes/loc ids/speed, schema v1 writer/loader, Python reference analysis (W3)

### Phase 10: Analysis Engine
**Goal**: The browser-side rules reproduce the workbook numbers at default settings and recompute correctly for any parameter change, with no UI required to prove it
**Depends on**: Phase 9
**Requirements**: CORE-01, CORE-02, CORE-03, CORE-04, CORE-05, CORE-06
**Success Criteria** (what must be TRUE):
  1. Running `node --test` shows golden-value tests passing: at defaults the engine yields the workbook class counts, eventos and impactos exactly
  2. Changing thresholds, offset or grouping gap changes classes, eventos, impactos, pontos and trecho priority (1 Alta → 4 Monitorar) consistently, with lower bounds inclusive
  3. Python↔JS parity tests with seeded random non-default parameters pass, so engine drift is caught automatically
  4. The engine exposes a "conforme planilha" state that is true only when settings are default and the trecho-independent KPIs equal the workbook
**Plans**: 5 plans

## Milestone Summary

**Status:** ✅ SHIPPED 2026-10-14. Phases 9-16, 47 plans. Audit: `tech_debt` with 50/50 requirements (`v1.3-MILESTONE-AUDIT.md`).

**Scope changes during the milestone:**
- Phase 11 moved the map and filter-driven map work to Phase 12 (MAP-06) and CSV upload to a new Phase 14 (UPLOAD-01).
- Phases 14 (CSV Upload), 15 (PDF Report) and 16 (Axis Orientation Popup) were added after the original 9-13 plan.

**Key decisions:**
- Raw logger CSVs are the primary source; the workbook is used only for validation (golden values).
- Trecho comes from station geofences and sentido from the station sequence. The terminal radius is 200 m with a forward-only state machine.
- Accel is stored as integer 1/2048 g counts. JS owns the analysis rules and Python owns quantization. The two are kept in step by Python↔JS parity fixtures.
- GPS precision stays at 6 dp in the public JSON (confirmed by the user, 2026-10-13).
- The map shows OSM relation routes per sentido instead of a GPS-fix track (12-06).
- IQ bands are ≥98 Bom, 90-98 Regular, <90 Ruim. The default GPS jump filter (50 km/h / 120 s) gives 98 pontos.
- The upload converter is a line-by-line JS port tested against a Python oracle fixture. CI is pinned to Python 3.13.14.
- The PDF is always the full run (filters ignored) with the current parameters; a map failure is only a warning.

**Issues resolved:**
- pt-BR Excel mangling recovered with exact counts. The 6-dp GPS publication decision was closed at the Phase 11 push.
- V8 `Math.log10` and CPython differences handled with a fixture-derived boundary table. `fromisoformat` ported and fuzz-verified.
- Stale ES-module caching during local preview fixed with `tools.serve_site` (no-cache).

**Issues deferred:**
- Per-trecho deviation at inferred stations (CTR/EQD/SCT): the fix is a larger radius or a closest-GPS-approach boundary, which needs a data regeneration and a JS converter update.
- MOB-01, RUN-01/02, CHART-06, UI-01, EXP-01, GEO-01 (future requirements).

**Technical debt incurred:**
- A PDF made before the routes load has no route lines.
- The quality card ignores the GPS filter.
- An upload-failure rollback loses the example URL state.
- No automated test covers `main.js` mount wiring.
- REQUIREMENTS MAP-01/MAP-02 wording does not match the shipped implementation.
- `09-VALIDATION.md` is not Nyquist compliant.
